## 真正發生的問題與處置

1. **測試環境限制**：最先用 `file://` 在沙盒 Chromium 開啟 HTML，遇到 `ERR_BLOCKED_BY_ADMINISTRATOR`；改用 `http://127.0.0.1` 也受到同樣限制。這是瀏覽器環境政策，不能據此斷定 HTML 本身有錯。改以 Playwright `set_content()` 注入同一份 HTML 原始碼，確認 DOM 與 JavaScript 互動正常。使用者 Windows 直開仍待驗收。
2. **截圖時機錯誤**：初次截圖在切換頁面後立即擷取，畫面仍在 CSS 淡入動畫中，文字顏色顯得偏淡。修改測試腳本，截圖前等待 360ms 後重跑，得到完整可讀的截圖。

3. **單檔發布連結風險**：最初在每頁來源列使用 `../wiki/*.md` 作為點擊連結。檢查部署方式時發現若只發布 `index.html`，這些相對 Wiki 連結將失效。修改成不會誤導使用者的 Wiki 頁名標籤，保留真正可點擊的 S01–S05 官方 URL，並在 `slide-source-audit.md` 保留完整對照，重新跑瀏覽器測試。

## 檢查前移與 Graph 反思

- 在生成 HTML 前先使用 `workflow/slide-plan.md` 確認「頁面 → Wiki → 來源 ID」的對應關係；對 2026-07-28 版本敏感內容先依 Wiki 核對，避免把舊版 `initialize` 流程當成新版必要操作。
- 在 HTML 產生後，以 Playwright 逐頁驗證，失敗時調整**測試方式**並重新檢查。
- 本次**沒有實作全自動內容自我修復 Loop**。內容與來源檢查主要由 LLM 在人工指示下進行；測試腳本可以重跑，但修正邏輯並未完全自動化。
